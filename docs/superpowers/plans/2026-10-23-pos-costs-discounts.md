# Plan

Implement shared adjustment validation/calculation, compact item/bill inputs and draft recovery. Recompute authoritative totals server-side and save immutable signed adjustment snapshots with receipts/order display. Protect saved snapshots from incompatible edits. Cover rounding, quantity, invalid/zero/negative totals, retry/stock safety, delivery exclusion and payment regression in unit, isolated database and browser tests. Build and deploy under resource limits with rollback and read-only live verification.

Validation: 1,269 unit tests, 19 isolated PostgreSQL tests, scoped TypeScript/lint and all 11 cashier Chromium flows passed. Browser coverage includes fixed and percentage item/bill adjustments, quantity changes without losing inputs, draft restoration, excessive discount rejection, receipt/order reconciliation, discounted lost-response retry with disabled adjustment fields and no duplicate snapshots, all payment methods, COD delivery/collection and mobile layout.

The mobile test exposed a two-pixel intrinsic-width overflow. Applying min-width:0 to the admin content flex item and adjustment fieldsets fixed it; the final rebuilt app passed the browser suite without diagnostic style overrides. Sequential production compile/generate stages passed in a 640 MiB container. Generation is repeated after isolated browser execution to discard test cache data. Release verification is read-only, and activation replaces only the app with the previous image retained for rollback. No migrations or live sales/provider charges/courier bookings are used for validation.
