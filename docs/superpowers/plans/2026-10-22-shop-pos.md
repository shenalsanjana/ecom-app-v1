# Shop POS implementation

Design: [Shop POS integration](../specs/2026-10-22-shop-pos-design.md).

1. Add optional order channel, receipt, cashier, payment and retry metadata with
   a migration and separate receipt sequence.
2. Add validated integer-cent cart/tender contracts and a serializable sale
   service using the existing stock allocation and audit helpers.
3. Add guarded product search and checkout actions, register-tab recovery and a
   responsive POS page with scanner support.
4. Add an admin-only print receipt and integrate POS history into Orders.
5. Verify money/auth rules, real Postgres concurrency/rollback/retries, build,
   types, lint, and browser cash/card/receipt/mobile flows. Document rollout.

Release checks also require keeping the category body component outside the
Next.js page module and the PayHere signature helper private to its route.
These preserve their existing behavior while satisfying generated route types.

Use a disposable local `pos_test` database on port 55432 for transaction and
browser validation. Never run fixture creation against the configured shop DB.

## Validation results

- Full Vitest suite: 1,254 passed; database-dependent suites remain opt-in.
- Isolated POS PostgreSQL suite: 9 passed, including rollback, duplicate intent
  handling and a shop/online race for the last available unit.
- Chromium POS flows: 5 passed, including a lost response after commit followed
  by refresh/retry, cash change, card approval reference, receipt PDF and mobile.
- Category/PayHere route regression tests: 30 passed after route export cleanup.
- Production build passed with webpack and one worker; type checking and lint
  were run separately. The ordinary Playwright suite still collects 64 tests
  and excludes the POS suite that requires its own disposable database.
