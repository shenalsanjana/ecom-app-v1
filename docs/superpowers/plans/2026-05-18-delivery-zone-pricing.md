# Delivery Zone Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the project's flat Rs.350 shipping fee with zone-based delivery pricing (Colombo Rs.350 / Other Rs.450, free over Rs.5000), drop Province and Postal Code from the address form and database, and rename customer-facing "Shipping" copy to "Delivery". Internal DB / code identifiers stay named `shipping*`.

**Architecture:** A new `app/_lib/delivery-zones.ts` module owns the city catalogue and the `zoneForCity` resolver. `app/_lib/checkout-config.ts` gains a zone-aware `calculateDelivery` (and the flat `calculateShipping` is removed once all callers move). A destructive Prisma migration drops four columns (`Address.region`, `Address.postalCode`, `Order.shippingRegion`, `Order.shippingPostalCode`). UI changes ripple from the cart → checkout → saved-address management → order list. Vitest covers the resolver and pricer; one Playwright e2e flow proves the cart total flips correctly between zones.

**Tech Stack:** Next.js 16 App Router (React 19), Prisma 6 + PostgreSQL, Zod 4, Vitest 4, Playwright 1.60, TypeScript 5.

```ts
// app/_lib/checkout-config.ts
// Shared so the client cart summary and the server action agree on totals.
import type { DeliveryZone } from "@/app/_lib/delivery-zones";

export const COLOMBO_DELIVERY_COST = 350;
export const OTHER_DELIVERY_COST = 450;
export const FREE_DELIVERY_THRESHOLD = 5000;

export function calculateDelivery(subtotal: number, zone: DeliveryZone): number {
  if (subtotal >= FREE_DELIVERY_THRESHOLD) return 0;
  return zone === "COLOMBO" ? COLOMBO_DELIVERY_COST : OTHER_DELIVERY_COST;
}
```
